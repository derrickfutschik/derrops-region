# region-bootstrap

AWS CDK (TypeScript) app for **region-level infrastructure** — the setup that
makes a given AWS region usable for workloads. Deploy this once **per region**
you want to light up, passing the region explicitly.

Its counterpart is [`derrops-account`](../derrops-account), which holds
**account-level** infrastructure (billing, budgets, alerting, global SSM
parameters). That app is deployed once per account and is pinned to `us-east-1`;
this one is deployed once per region and is pinned to none.

| | `derrops-account` | `derrops-region` (this repo) |
| --- | --- | --- |
| Scope | the whole AWS account | one AWS region |
| Deployed | once | once per region |
| Region | fixed `us-east-1` (billing metrics only exist there) | `-c region=<aws-region>`, required |
| Stacks | parameters, alerting, budget | network, bastion |

## Deploying a region

```bash
# Once per account+region, if the CDK has never been used there:
npx cdk bootstrap aws://<account-id>/ap-southeast-2

npx cdk deploy --all -c region=ap-southeast-2
```

The region is **required** — there is no default. Every stack name here is
identical in every region (AWS scopes them per-region), so an accidentally
omitted region would be invisible in `cdk diff`; the app throws instead.

## Naming conventions

Names in this repo are **never hand-assembled**. Every name is generated by
[`derrops-conventions`](https://www.npmjs.com/package/derrops-conventions) from
an ordered set of segments, so names stay consistent and parseable. This app's
org segment is always `derrops` and its domain segment is always `region`; each
stack picks its own `service`.

```
{org} -- {domain} -- {service} -- {key}
  │        │           │            └─ the specific resource (e.g. instance-id)
  │        │           └────────────── deployable unit    (e.g. bastion)
  │        └────────────────────────── scope              (always region here)
  └─────────────────────────────────── org boundary       (always derrops)
```

Segments join with `--`; words within a segment join with `-`. The same segments
drive a stack's resource names, its stack name, its CDK construct id, its
resource tags, and its doc filename under [`docs/`](docs/). The only identifier
that is *not* the convention name is the TypeScript **class** (e.g. `VpcStack`),
since `--` is not a legal identifier.

Names are **not** region-qualified, deliberately: everything named here is
region-scoped by AWS, so the same name in two regions is two independent
resources. The single exception is the bastion's IAM role, which is
account-global and therefore left unnamed — see
[`docs/derrops--region--bastion.md`](docs/derrops--region--bastion.md).

> Contributing a new stack? The setup procedure and naming rules live in
> [`CLAUDE.md`](CLAUDE.md).

## Stacks

Each stack is documented in its own file under [`docs/`](docs/), named after the
stack's generated name. Deploy order (enforced via `addDependency`):
`derrops--region--network` → `derrops--region--bastion`, since the bastion
consumes the VPC's public subnets.

## Reading account-level config

Account-wide parameters (alert recipients and friends) are owned by
`derrops-account` and live in SSM **in `us-east-1`**. Read them at runtime with
an explicit region — CloudFormation dynamic references cannot cross regions at
all, so there is no synth-time shortcut:

```bash
aws ssm get-parameter --region us-east-1 \
  --name /derrops/account/alert/emails --query Parameter.Value --output text
```

## Useful commands

All of these need `-c region=<aws-region>`:

- `npm run build` — compile TypeScript
- `npm test` — run the Jest assertion tests (no region needed; tests set their own)
- `npx cdk list --long -c region=ap-southeast-2` — list stacks + target environment
- `npx cdk synth -c region=ap-southeast-2` — emit the synthesized template(s)
- `npx cdk diff -c region=ap-southeast-2` — compare against what's deployed there
- `npx cdk deploy --all -c region=ap-southeast-2` — deploy

Per-stack deploy-time configuration (CDK context, props) is documented in each
stack's file under [`docs/`](docs/).
